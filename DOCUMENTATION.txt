1. EXECUTIVE OVERVIEW & PLATFORM PURPOSE
================================================================================
NCORE 2026 12HRS HACKATHON is an enterprise-grade, real-time web application
purpose-built to manage a prestigious national-level hackathon.

The application serves three distinct user groups:
  1. Student Innovators (Teams of up to 4 members)
  2. Hackathon Directors & Admins (Organizers / Faculty Coordinators)
  3. Evaluation Committee & Jury Members (Academic & Industry Experts)

Primary Objectives of the Platform:
- Provide a clean, light-themed, futuristic web interface inspired by modern
  aerospace and engineering command centers.
- Guarantee seamless team registration with automatic 4-member rosters and
  cryptographic random passkey generation.
- Eliminate all administrative / jury clutter from the public landing page,
  keeping the focus solely on hackathon participants.
- Provide a secret, discreet double-tap mechanism on the version tag (v2.4.1)
  to unlock Director and Jury gateways without exposing them publicly.
- Deliver synchronized round progression timers controlled by the Director.
- Enable live multi-criteria jury scoring with real-time tournament re-ranking.
- Provide on-campus location verification (restricted to Arunai Engineering
  College campus radius) for certificate issuing without exposing technical
  coordinates to participants.

2. TECHNOLOGY STACK & ARCHITECTURAL FOUNDATION
================================================================================
The web application is engineered with zero external server dependencies,
providing a high-performance Single Page Application (SPA):

- Core Framework: React 18.3.1 (Strict Mode & Functional Components with Hooks)
- Build System & Bundler: Vite 6.4.3 (ESNext bundling, Sub-10s production build)
- Styling & Layout: Tailwind CSS 3.4.17 with custom utility classes, HUD corner
  accents, and responsive grid layouts.
- Routing Architecture: Native HTML5 History API Routing via HackathonContext
  (Zero react-router peer dependency conflicts, supports browser back/forward,
  clean URLs: '/', '/login', '/admin', '/jury').
- Iconography: Lucide React (Clean, vector iconography).
- Audio Synthesizer: Custom Web Audio API utility (Procedural synthesized audio
  for clicks, alerts, warps, and success chimes with global mute toggle).
- Certificate Renderer: Pure HTML5 Canvas 2D Rendering Engine (1200x800px,
  dual gold/cobalt borders, parchment radial shading, dynamic convener signatures,
  and anti-forgery cryptographic hash generation).
- Data Persistence: Browser LocalStorage with automatic hydration and real-time
  synchronization across tabs.

3. USER ROLES & ACCESS CONTROL ARCHITECTURE
================================================================================
The application enforces three distinct authorization tiers:

1. PARTICIPANT / TEAM ROLE ('team'):
   - Can register a team with up to 4 members.
   - Obtains an auto-generated Team ID (e.g. NCORE-T101) and random passkey
     (e.g. NVG-9021-X).
   - Can log in via Team ID + Passkey or Team Leader Email + Password.
   - Accesses the Participant Dashboard: submits round deliverables, views live
     standings, checks Director announcements, and downloads verified certificates.

2. HACKATHON DIRECTOR / ADMIN ROLE ('admin'):
   - Access Gate: Restricted passcode ('admin123' or one-click demo login).
   - Accessed via /admin or through the secret v2.4.1 double-tap on the login panel.
   - Has absolute authority over:
     * Round phase transitions (Round 1, Round 2, Round 3, Standby, Active, Paused).
     * Live Countdown Timer (Start, Pause, Reset, Custom minute duration overrides).
     * Campus Geofence Certificate Switch (Locks or enables certificate issuance).
     * Leaderboard Publication State (Draft mode vs. Live public rankings).
     * Real-time Broadcast Transceiver (Sends critical alerts to participants).
     * Roster Inspection & Schedule Milestone activation.

3. JURY EVALUATION COMMITTEE ('jury'):
   - Access Gate: Requires Jury password ('jury123', 'ncore2026', or one-click demo login).
   - Evaluator Profiles: Mrs. V. Umadevi (HOD UG, CSE), Dr. P. Anandan (Professor,
     CSE), Dr. S. K. Narayanan (Industry AI Architect), and Guest Evaluators.
   - Accessed via /jury or through the secret v2.4.1 double-tap on the login panel.
   - Has full access to:
     * Team deliverable inspection (R1 Blueprint, R2 GitHub, R3 Demo links).
     * Multi-round scoring inputs (Round 1 /100, Round 2 /100, Round 3 /100).
     * Qualitative feedback textarea for written jury critique.
     * Instant score commitment that recalculates total scores and standings.
     * Tournament Scoreboard and CSV audit export.

5. CORE FUNCTIONAL OPERATIONS & WORKFLOWS
================================================================================

--------------------------------------------------------------------------------
5.1 Team Registration & Random Passkey Generation
--------------------------------------------------------------------------------
1. User clicks 'REGISTER TEAM' in the navbar or landing page hero.
2. User selects Challenge Domain and enters Team Name, Leader Name, Email,
   Phone, College, Department, and Academic Year.
3. User adds up to 3 additional team members (Total 4 members: Leader + 3 members).
   Each member is assigned a name and specialization role.
4. On submit, the system:
   - Formats a new Team ID: 'NCORE-T' + sequential index (e.g. NCORE-T105).
   - Generates a cryptographically random passkey using the team prefix, 4-digit
     number, and check letter (e.g. 'CYB-4812-F').
   - Initializes R1, R2, R3 scores to 0.
   - Displays a success dialog with the generated credentials and copy button.
   - Persists the team into LocalStorage ('ncore_teams').

--------------------------------------------------------------------------------
5.2 Participant Login & Secret Committee Gateway
--------------------------------------------------------------------------------
1. User clicks 'TEAM LOGIN' in navbar or navigates to http://localhost:3000/login.
2. For Participants:
   - Enters Team ID and Passkey (or Leader Email + Password).
   - System authenticates credentials and opens the Participant Dashboard.
3. For Director & Jury (Hidden Access):
   - Double-clicks or double-taps the tiny 'v2.4.1' label in the bottom-right corner.
   - The panel immediately unlocks the "COMMITTEE GATEWAY".
   - Clicking 'LAUNCH JURY SCORING PAGE' routes to /jury.
   - Entering passcode 'admin123' routes to /admin.
   - Double-tapping 'v2.4.1' again returns to participant login.

--------------------------------------------------------------------------------
5.3 Multi-Round Submission Lifecycle
--------------------------------------------------------------------------------
1. Participant navigates to the 'PROJECT & MILESTONES' tab in their dashboard.
2. In Round 1: Inputs Architecture Blueprint URL (Figma/PDF/Drive), Tech Stack,
   and Problem Abstract.
3. In Round 2: Inputs GitHub Repository URL and Prototype build link.
4. In Round 3: Inputs Live Demo URL (e.g. Vercel, Netlify, Cloud Run).
5. On clicking [SUBMIT ROUND ARTIFACTS], the team's record is updated and
   immediately reflected in the Jury Evaluation Workbench.

--------------------------------------------------------------------------------
5.4 Director Command Operations
--------------------------------------------------------------------------------
1. Director accesses http://localhost:3000/admin.
2. Enters passcode 'admin123' (or clicks demo login).
3. Selects the active round (e.g. Round 1).
4. Chooses round duration (e.g. 2 hours or custom 45 minutes).
5. Clicks [START ROUND TIMER]:
   - Global timer state turns ACTIVE.
   - An automatic broadcast announcement is dispatched to all participants.
   - Countdown clocks across all participant and jury screens begin ticking.
6. When evaluations conclude, Director switches 'CAMPUS CERTIFICATES' to ENABLED.
7. Director toggles 'LEADERBOARD' from DRAFT to LIVE to make standings public.

--------------------------------------------------------------------------------
5.5 Jury Evaluation Operations
--------------------------------------------------------------------------------
1. Evaluator accesses http://localhost:3000/jury.
2. Selects their evaluator identity from the dropdown.
3. Selects a team from the left workbench roster.
4. Clicks the submission links to inspect code and architecture.
5. Enters marks: Round 1 (out of 100), Round 2 (out of 100), Round 3 (out of 100).
6. Enters qualitative written comments for team feedback.
7. Clicks [COMMIT & SAVE EVALUATION]:
   - Scores are recorded with the evaluator's name and timestamp.
   - Leaderboard standings are automatically re-sorted.
   - Data is persisted to LocalStorage.
8. Evaluator switches to the 'STANDINGS SCOREBOARD' tab to review rankings.
9. Clicks [DOWNLOAD EVALUATION CSV] to save the audit trail spreadsheet.

--------------------------------------------------------------------------------
5.6 Location-Based Certificate Verification & Canvas Generation
--------------------------------------------------------------------------------
1. Participant opens the Certificate Center from their dashboard.
2. System checks if Director has unlocked certificate issuance:
   - If locked: Displays warning banner that issuance is pending Director release.
3. If enabled, participant clicks [VERIFY DEVICE GPS]:
   - Device requests browser geolocation permissions.
   - Latitude and longitude are processed against campus center (12.1922, 79.0833).
   - If inside 2.5 km campus radius: status turns green (GEOFENCE VERIFIED).
   - If outside: access is denied with a strict campus presence requirement message.
4. Participant selects their name from the team member list.
5. Clicks [GENERATE OFFICIAL CERTIFICATE]:
   - HTML5 Canvas renders the high-res 1200x800 certificate with gold borders,
     official convener signatures, and an anti-tamper hash.
6. Participant clicks [DOWNLOAD PNG] to save the certificate image file.

7. GEOFENCING MATHEMATICS & SECURITY MODEL
================================================================================
Location verification enforces strict physical presence using the Haversine
formula:

Campus Target Anchor:
- Latitude:  12.1922° N
- Longitude: 79.0833° E
- Location:  Arunai Engineering College, Velu Nagar, Mathur, Tiruvannamalai - 606 603
- Radius:    2,500 meters (2.5 km)

Haversine Formula Implementation:
  R = 6371000 meters (Mean Earth Radius)
  dLat = (userLat - campusLat) * (PI / 180)
  dLon = (userLon - campusLon) * (PI / 180)
  a = sin²(dLat / 2) + cos(campusLat * PI / 180) * cos(userLat * PI / 180) * sin²(dLon / 2)
  c = 2 * atan2(√a, √(1 - a))
  distanceInMeters = R * c

Security Rules:
- If distanceInMeters <= 2500m: Verification passes.
- If distanceInMeters > 2500m: Verification strictly rejected.
- Coordinates are NEVER displayed in the participant certificate download menu.
- Admin testing override is only accessible when authenticated as Director.
